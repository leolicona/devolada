# Bug Fix: a transfer made after SPEI's 18:00 date change is never found by its reference

- **Slug**: spei-date-rollover
- **Fixed**: 2026-09-25
- **Assessment**: ./assessment.md
- **Status**: applied

## Summary

A search by referencia numérica now asks Banxico the **operation day**
instead of the calendar day. The rule works in Mexico City time: from 18:00
it asks the next day, before that the same day. The time comes from the
receipt when it prints one, which the reader now reads and records.
Otherwise the submission time stands in. After a `not_found`, the next retry
asks the other day, at no extra paid call. A clave search is unchanged. The
server's fallback date and the manual form's "today" now use the business's
day instead of the UTC date.

## Deviations from Assessment

1. **`pending` asks the same day again.** The assessment said each later
   by-reference call asks "the other date from the one the row's previous
   by-reference call asked". Reading the lifecycle showed that a `pending`
   answer means Banxico **found** the transfer in process on that day.
   Switching would spend the next slot on a day known to be wrong. So only
   a `not_found` hands over the other day. `pending`, or a call that never
   answered, asks the same day again. It is covered by the test "pending on
   a day asks the same day again".
2. **Scope expansion, logged:** `apps/api/test/consta/helpers.ts` gains
   `hora` on the reader stub's type. It is a test helper that the file list
   did not name.
